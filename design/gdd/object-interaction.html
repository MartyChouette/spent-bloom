Overview

The Object Interaction system lets the player pick up, carry, and place objects throughout the apartment using a spring-damper physics model. Objects float toward a target point driven by the mouse cursor, with five authored feel presets that govern how each object archetype handles momentum and resistance. Placement uses a ghost-preview renderer with an 11-step validation cascade, grid snapping, and magnetic snap zones for contextually appropriate placement targets. Items that belong together — shoes, dishes, books — snap and stack via the PairableItem system. A highlight system with six priority layers pulses to draw attention to interactive items.

Player Fantasy

The player should feel like they are tidying up with gentle, satisfying weight. Heavy objects should feel like they have mass; small trinkets should feel nimble and responsive. Placing something in exactly the right spot — a shoe paired with its partner, a dish stacked on its pile — should feel like a small click of rightness. The apartment should reward attentiveness: magnetic snaps guide rather than force, and the ghost preview communicates intent before commitment.

Pickup Feel Ramp

When an object is first picked up, there is a 0.25-second blend from carry parameters (spring=250, damper=22, maxAccel=120, angularDamp=16) into the object's assigned preset. This prevents the object from immediately flying to the cursor.

blendParam = min(timeSincePickup / 0.25, 1.0) spring = Lerp(250, presetSpring, blendParam) damper = Lerp(22, presetDamper, blendParam) maxAccel = Lerp(120, presetMaxAccel, blendParam) angularDamp= Lerp(16, presetAngularDamp, blendParam) // At t=0: tight carry feel (spring=250) // At t=0.25: full preset feel

Grid Snapping

  • Grid cell size: 0.06 meters base
  • Edge margin: 0.03 meters (objects cannot be placed closer than 0.03m to surface edge)
  • Wall-surface multiplier: 1.0x currently (planned 2–3x for coarser wall placement)

Placement Rejection Cascade

Before a placement is confirmed, 11 checks run in order. The first failure rejects placement and turns the ghost red. If check 3 fails, checks 4–11 do not run.

Click any check to expand its details.

  • 1
    Surface check
    >
    A valid PlacementSurface must be under the candidate position. If no surface exists at the cursor, placement fails immediately.
  • 2
    Wall mount check
    >
    If the surface is a wall, the object must be flagged as a wall-mountable type. A standard shelf item dropped onto a wall surface is rejected here.
  • 3
    Fridge state check
    >
    If placing inside a fridge, the fridge door must be open. A closed fridge door blocks any placement inside the fridge volume.
  • 4
    Cubby state check
    >
    If placing inside a cubby, the cubby door must be open. Same logic as fridge — closed door = blocked placement.
  • 5
    Trash category check
    >
    If placing in a trash zone, the object's category must match the zone's accepted category. A food item cannot go in a paper trash zone.
  • 6
    Height clearance check
    >
    The object's bounding box must fit within the surface's vertical clearance. A tall item under a low shelf fails this check.
  • 7
    Barrier sphere check
    >
    A sphere of radius 0.009 meters is cast at the candidate position. Any collision with a barrier collider rejects placement. Catches near-miss placements clipping into thin geometry (baseboards, trim) that the footprint check does not detect.
  • 8
    Exclusion zone check
    >
    The candidate position must not overlap any active exclusion zone volume. Exclusion zones are designer-placed colliders that block specific spots from receiving objects.
  • 9
    Footprint overhang check
    >
    The object's footprint must be at least 50% supported by the surface. No more than 50% may overhang the edge. Prevents balancing objects on the corner of a shelf.
  • 10
    Occupancy check
    >
    The grid cell at the candidate position must not already be occupied by another placed object. Non-pairable items cannot share a cell. (Stacking via PairableItem bypasses this check.)
  • 11
    Reserved
    >
    Reserved for future use or additional game-specific checks. Currently always passes.

Magnetic Snap Zones

Certain placement targets pull the held object into a precise position when within snap range. Snaps are evaluated every frame while the object is held.

Double-Click to Unstack

If the player double-clicks a stacked item within a 0.3-second window, the entire stack is broken and all items are individually grabbable. Outside this window, clicking grabs only the top item.

ActionResult
Single click stacked itemGrabs the top item only
Double-click within 0.3s windowBreaks entire stack — all items individually grabbable
Double-click after 0.3s windowTreated as two single clicks; grabs top item twice
Double-click on solo item (no stack)Treated as standard grab — no feedback

Rotation

While holding an object, pressing RMB rotates it in 45-degree steps. Wall rotation is preserved when replacing on the same wall; floor placement always uses cursor-facing rotation.

Tether and Wall Collision

  • Tether distance: 3 meters from grab origin. If exceeded, object snaps back to grab origin with velocity zeroed
  • Wall collision: Velocity clamped against wall colliders — object cannot be pushed through a wall by spring force

Spring-Damper Force

force = (targetPosition - objectCenter) * spring - velocity * damper clampedForce = Clamp(force magnitude, 0, maxAccel) in force direction Variables: targetPosition: world-space cursor target on carry plane objectCenter: world-space center of held Rigidbody spring: preset spring constant (e.g. 120 for Default) damper: preset damper constant (e.g. 18 for Default) maxAccel: maximum force magnitude (e.g. 60 for Default) Example (Default, object 0.5u from target, velocity 1 u/s toward target): force = 0.5 * 120 - 1.0 * 18 = 60 - 18 = 42 u/s² 42 < maxAccel(60), so force = 42 u/s²

Edge Cases

Pair snap consumed

Once a SpecificPartner pair bond forms, the snap zone deactivates. Picking up one shoe and moving it elsewhere does not re-enable the snap; the player must deliberately re-place.

Double-click on top of a single item

If a solo item (no stack) is double-clicked, the double-click is treated as a standard grab. No unstacking animation or feedback plays.

Wall rotation on floor drop

If an object with wall rotation is dropped on a floor surface, the rotation resets to the default floor-facing orientation. It is not preserved across surface types.

Barrier sphere at 0.009m

Intentionally very small — it catches near-miss placements clipping into thin geometry (baseboards, trim) that the footprint check does not detect. Objects with very thin footprints may still fail this check in tight corners.

Tether distance

At exactly 3.0 meters, the snap-back triggers. The object teleports to the grab origin, not to the cursor. Velocity is zeroed at snap-back to prevent oscillation.

Ghost during magnetic snap

When a magnetic snap is active, the ghost preview moves to the snap target position rather than the grid-snapped cursor position. The 11-step cascade still runs against the snap position. If the snap position fails validation, the ghost turns red but the snap remains visually active.

Stacked item occupancy

Each item in a stack occupies the same grid cell. Occupancy check passes for stacking (handled by the PairableItem Stacked path before the occupancy check runs), but a non-pairable item cannot be placed in the same cell as any stack member.

Fridge/cubby with closed door

If a door closes while an item is inside, the item is not ejected. The cubby-state check only applies at placement time.

Render queue conflict

Held objects at queue 3900 render on top of UI elements that render below that queue. If a UI panel uses queue < 3900, a held object will visually clip through it. This is known and accepted for the current UI stack.

Acceptance Criteria

  • ✓Snappy preset: Pick up a Snappy-preset object. Move cursor quickly. Object must reach cursor in under 0.1 seconds from 0.5 units away. Release and verify no significant oscillation.
  • ✓Pickup ramp: Pick up a Plucky-preset object (spring=35). At frame of grab, spring must be 250. At 0.25s post-grab, spring must be 35. Intermediate values must be a linear lerp.
  • ✓Ghost validity: Hold an object over a valid surface — ghost must display green (0.5, 0.95, 0.55, 0.35). Move over an occupied cell — ghost must turn red (0.95, 0.2, 0.2, 0.35).
  • ✓11-step cascade — occupancy: Place an object on a grid cell. Attempt to place a second non-pairable object in the same cell. Placement must be rejected (red ghost) and no overlap occurs.
  • ✓Pair snap teleport: Place one shoe. Hold the partner shoe within 0.4m of the first. The held shoe must immediately teleport to the snap position — no lerp visible.
  • ✓Trash snap quadratic pull: Hold a trash item at 0.8m from a trash zone. Verify zero pull force. Move to 0.4m. Verify pull increases. At 0.01m, verify pull is near maximum.
  • ✓Double-click unstack: Stack three dishes. Double-click the top dish within 0.3 seconds. All three dishes must be individually grabbable afterward.
  • ✓Double-click timeout: Stack two dishes. Wait 0.4 seconds, then double-click. Only the top dish is grabbed — the lower dish remains placed.
  • ✓Tether snap-back: Hold an object and drag the cursor 3.1 meters from grab origin. Object must snap back to grab origin. Velocity must be zero immediately after snap-back.
  • ✓Highlight pulse: Hover over an interactive object. Verify highlight pulses at 3 Hz (one full cycle in 0.333 seconds), with intensity never dropping below 0.7.
  • ✓RMB rotation preserved on wall: Place an object on a wall. Pick it up. Do not rotate it. Replace on same wall. Verify object returns to pre-pickup wall rotation.
  • ✓Held render-on-top: Pick up an object and drag it in front of furniture. The held object must render on top of the furniture geometry.
