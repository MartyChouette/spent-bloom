Overview

The accessibility system exposes 16 settings across 6 categories — Visual, Audio, Motion, Timing, Controls, and Performance — through a static utility class. No MonoBehaviour is required.

AccessibilitySettings reads and writes PlayerPrefs with an "Iris_" prefix, fires a batched OnSettingsChanged event when values change, and is domain-reset-safe. Every setting has a documented default, a defined safe range, and a clear system contract.

Player Fantasy

Every player deserves to experience the apartment on their terms. The player who is motion-sensitive should not have to endure swimming geometry to enjoy the story. The player with two hours should not be timed out of a date. The player with hearing loss should not miss narrative information conveyed only through audio.

Good accessibility design should feel like the game was always meant to work this way — not like a concession bolted on afterward.

Architecture

AccessibilitySettings is a static class (no MonoBehaviour, no scene object required). All state lives in PlayerPrefs under the "Iris_" prefix. Key APIs:

APIDescription
Static properties (get/set)One per setting, with range clamping on read
OnSettingsChangedStatic C# event fired when any setting changes
BeginChanges() / EndChanges()Batch wrapper: defers event until EndChanges(), fires once regardless of how many settings changed
ResetAll()Wipes all "Iris_" PlayerPrefs keys, restores defaults, calls ScalableBufferManager.ResizeBuffers(1, 1)
[RuntimeInitializeOnLoadMethod]Clears all static event subscribers on domain reload, preventing stale subscriptions

All systems that respond to settings changes subscribe to OnSettingsChanged and read the relevant property. They do not receive the specific setting that changed — they read what they care about.

Timer Multiplier Comparison

Adjust the base timer duration and see how each option scales it. Formula: actualDuration = designedDuration × TimerMultiplier

Designed duration (seconds): 120s

NoTimer Behavior

When TimerMultiplier = 0 (NoTimer), actualDuration = 0. In implementation, this means the timer never counts down — it is treated as infinite. A timer already running when the setting changes is not retroactively adjusted. The new multiplier only applies to timers started after the change.

AmbienceVolume & MoodMachine Interaction

MoodMachine adjusts ambience dynamically in a 0.3 – 0.6 range based on mood. AccessibilitySettings.AmbienceVolume scales the entire AudioMixer group. If AmbienceVolume=0.5, the effective range becomes 0.15 – 0.3.

MoodMachine must read AmbienceVolume and scale its output accordingly. It must not write absolute values to the mixer group — that would override the accessibility setting.

Edge Cases

ResetAll during active play session

All settings revert to defaults. A timer currently running at Relaxed speed is not retroactively adjusted — it continues at its original calculated duration. The new TimerMultiplier applies only to timers started after the reset.

BeginChanges/EndChanges nesting

Nesting these calls is not supported. A second BeginChanges() before EndChanges() is a bug. The system should log a warning if called while already in a batch.

PlayerPrefs corruption (out-of-range value)

If a stored value is outside its defined range (e.g., TextScale = 5.0), the property getter should clamp to the safe range on read and re-write the clamped value. This prevents downstream systems from receiving out-of-range values. Example: "Iris_TextScale" = 99.0 → reads as 1.5, re-writes 1.5.

AmbienceVolume interaction with MoodMachine

MoodMachine adjusts ambience dynamically in a 0.6→0.3 range. AmbienceVolume scales the AudioMixer group. If AmbienceVolume=0.5, the effective range becomes 0.3→0.15. Both can be 0 simultaneously (silent ambience); this is valid. MoodMachine must multiply its output by AmbienceVolume rather than writing absolute values.

CaptionsEnabled with no caption text authored

The caption overlay displays nothing. No error. Missing caption data should be flagged during content review, not at runtime.

TextScale at 1.5 overflowing UI containers

This is a UI layout bug, not an accessibility bug. All UI containers must be tested at TextScale=1.5 before release. The accessibility system provides the value; layout is the SettingsPanel designer's responsibility.

InvertScroll applied to mouse wheel in UI lists

All scrollable lists must route through the centralized scroll accessor. Any list that reads Input.mouseScrollDelta directly will not respect InvertScroll and must be refactored.

QualityPreset=-1 on unrecognized device

The auto-detection path must have a fallback to the lowest quality preset rather than throwing an unhandled exception.

Domain reload in editor

[RuntimeInitializeOnLoadMethod] clears all static event subscribers. Any system that subscribes in Awake will resubscribe on the next play session. Static subscriptions from editor tooling must resubscribe manually.

Acceptance Criteria

  • ✓PlayerPrefs persistence: set TextScale to 1.3, quit and relaunch, confirm TextScale reads as 1.3 without manual re-application.
  • ✓OnSettingsChanged fires once per BeginChanges/EndChanges block: change 3 settings inside the block. Confirm event fired exactly once.
  • ✓ResetAll restores all defaults: modify all 16 settings to non-default values. Call ResetAll(). Confirm all 16 match documented defaults. Confirm ResizeBuffers(1,1) was called.
  • ✓ColorblindMode Deuteranopia: all semantic "happy" indicators display blue. All semantic "sad" indicators display orange.
  • ✓ReduceMotion suppresses vertex snap: enable ReduceMotion. PSXLit object moves without vertex snapping. Change took effect within one rendered frame.
  • ✓ReduceMotion live update: toggle ReduceMotion from false to true while running. Vertex snap stops within one frame without restart.
  • ✓TimerMultiplier Extended doubles timer: designed duration 60s, set Extended (2.0). Timer runs for 120 seconds before expiring.
  • ✓TimerMultiplier NoTimer: set NoTimer. Start timed interaction. Confirm timer never expires regardless of elapsed time.
  • ✓ResolutionScale=0.5 halves buffer dimensions: confirm ScalableBufferManager.ResizeBuffers(0.5, 0.5) was called.
  • ✓PSXEnabled toggle via setting: set to false. PSXPostProcessFeature is disabled (no downscale or dithering). Set to true. Effect returns.
  • ✓InvertScroll inverts scroll delta: set InvertScroll=true. Scroll up. Confirm accessor returns negative delta. All scrollable UI panels respond correctly.
  • ✓TextScale at 1.5 does not clip: set TextScale=1.5. Navigate every UI panel. No text is clipped, truncated, or overflows its container.
  • ✓AmbienceVolume and MoodMachine coexist: set AmbienceVolume=0.5. Let MoodMachine shift mood 0 to 1 (range 0.6→0.3). Confirm audible range is approximately 0.3→0.15 (halved).
  • ✓_suppressCallbacks prevents loop: open SettingsPanel. Confirm populating controls does not trigger any OnSettingsChanged events (verify with test listener counting events during panel open).
  • ✓Domain reload clears subscribers: in editor, subscribe a test listener, exit play mode, enter play mode again. Confirm test listener from previous session is no longer subscribed.
  • ✓PlayerPrefs range clamping: manually write TextScale=99.0 to "Iris_TextScale". Launch game. Confirm AccessibilitySettings.TextScale reads as 1.5 (clamped) and PlayerPrefs key rewritten to 1.5.
